# Pair Agent P0.5 Shared Conversation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the P0.5 shared-conversation bridge, passive cross-Agent context, bounded peer messaging, Pair Session Events inspection, and Pair-level message inputs on top of the existing Phase 0 DSH prototype.

**Architecture:** Keep the two DSH Agent Sessions independent and make the Pair Ledger the only shared-context authority. A Host-owned bridge observes public DSH `session/event` notifications, flushes and rereads each Session's durable prefix, derives idempotent Pair Events and links, while request composition consumes Pair Events plus only the active Agent's local history. Explicit peer communication appends a directed Pair Event before waking the recipient; ordinary messages never wake the peer.

**Tech Stack:** TypeScript 5.9, Node.js 22, pnpm 11.7, Vitest, React 18, native Node HTTP/SSE, DSH fixed fork at `dsh.lock.json`, OpenAI Chat Completions-compatible provider boundary.

- [ ] **Step 5: Implement canonical idempotency inside Pair mutation serialization**

`PairDerivedEventWriter` belongs to `packages/runtime` and receives `PairRegistry`, not only `JsonlPairLedgerStore`, so every successful append updates the Registry projection/subscribers and shares the same per-Pair mutation queue as user commands. Do not import Runtime from Ledger.

The current `runPairMutation()` intentionally allows one command event. Preserve that contract. Add a separate internal `runDerivedMutation()` whose context supplies the current Ledger prefix and an ordered `appendDerived()` function, folds each durable record in order, and publishes the resulting Projection after the group attempt. It must reuse the same `serializePairMutation()` queue and must never become a public user-command path. If any CAS conflicts with an append performed outside Registry, replay the latest prefix, rebuild the source index and rerun the whole callback.

`runDerivedMutation()` is allowed for Registry-owned Pair states `creating`, `recovering` and `ready`; it must not call `getReadyPair()` or trigger recovery recursively. It reads the durable Pair prefix directly while holding the mutation queue, requires an existing canonical `pair.created`, and rejects missing/failed/closing ownership. DSH create/resume and Bridge catch-up themselves run **outside** this queue; only the short lifecycle state transitions and derived append groups enter it.

```ts
export interface DerivedEventSpec {
  readonly sourceId: string;
  /** Required only for session_event.linked; resolved to `${pairId}:${seq}` under the mutation lock. */
  readonly representedSourceId?: string;
  readonly draft: PairEventDraft;
}

export class PairDerivedEventWriter {
  constructor(private readonly registry: PairRegistry) {}

  async appendGroup(pairId: PairId, specs: readonly DerivedEventSpec[]): Promise<PairEvent[]> {
    return this.registry.runDerivedMutation(
      pairId,
      async ({ events, appendDerived }) => {
        const bySource = indexCanonicalSources(events);
        const output: PairEvent[] = [];
        for (const spec of specs) {
          const existing = bySource.get(spec.sourceId);
          if (existing !== undefined) {
            assertCanonicalDerivation(existing, spec);
            output.push(existing);
            continue;
          }
          const event = await appendDerived(withSourceId(spec.draft, spec.sourceId));
          bySource.set(spec.sourceId, event);
          output.push(event);
        }
        return output;
      },
    );
  }
}
```

`session_event.linked.payload.pairEventId` cannot be finalized by the pure derivation step when the represented message has not been appended yet, because its Pair `seq` is store-owned. The link spec therefore carries `representedSourceId`; `PairDerivedEventWriter` resolves the already-present or newly appended represented message under the same mutation lock and replaces the provisional `pairEventId` with `${pairId}:${seq}` before validation and append. An existing link whose represented source is absent is an orphan and fails closed before any repair append.

Add read-only `PairRegistry.readEvents(pairId)` and `readSnapshot(pairId)` methods inside the same mutation queue instead of exposing the store publicly. They are for callers outside a mutation callback; do not call them recursively from `runDerivedMutation()`. `readSnapshot()` returns Projection plus the matching Ledger prefix for snapshot-consistent Event API reads. `assertCanonicalDerivation()` compares normalized type, actor, source, channel, visibility, authority, refs and payload; `occurredAt`, `seq` and `pairId` remain store-owned. Duplicate source IDs in two existing events are corruption, even if their payloads match.

Before append, call `assertP05PairEventPayload()` for P0.5 event drafts. Add the explicit half-write matrix to tests: neither present, message only, both present, and orphan link; the orphan link case fails closed.

- [ ] **Step 3: Implement the per-Session drain state machine**

```ts
interface DrainState {
  nextSeq: number;
  dirty: boolean;
  running?: Promise<void>;
}

export class SessionToPairBridge {
  readonly #state = new Map<string, DrainState>();
  #off?: () => void;
  #closing = false;

  markDirty(sessionId: string): void {
    const state = this.#state.get(sessionId);
    if (state === undefined || this.#closing) return;
    state.dirty = true;
    state.running ??= this.#drainLoop(sessionId, state).finally(() => {
      state.running = undefined;
      if (state.dirty && !this.#closing) this.markDirty(sessionId);
    });
  }

  async whenCaughtUp(sessionIds?: readonly string[]): Promise<void> {
    await waitForStableDrainSnapshot(this.#state, sessionIds);
    this.assertHealthy();
  }
}
```

The synchronous hook may validate and enqueue only. `#drainLoop()` must await `flushSession()`, then `readDurableFrom(nextSeq)`, derive groups, append each group through `PairDerivedEventWriter`, and advance `nextSeq` only after the whole returned durable prefix is accounted for. Store a rejected drain as Bridge health state and notify the Registry/Host; do not throw from the observer and assume DSH will surface it.

- [ ] **Step 5: Wire recovery and shutdown order**

Avoid the Adapter → Registry dependency cycle with two stages:

1. Adapter construction creates `DshSessionObservationHub` and immediately installs the one global Context `session/event` hook. The Hub has no Registry dependency and rejects events for unknown Session IDs.
2. After Adapter creation, construct Registry, `PairDerivedEventWriter` and `SessionToPairBridge`, then call `adapter.attachPairBridge(bridge)` before any `createPair()` or `recoverPair()` call. A second attach or Agent preparation before attach fails closed.

```ts
const runtime = await launchDshPairWebRuntime(adapterOptions);
const registry = new PairRegistry(store, runtime.adapter);
const writer = new PairDerivedEventWriter(registry);
const bridge = new SessionToPairBridge(runtime.adapter.observationPort(), writer);
runtime.adapter.attachPairBridge(bridge);
```

`preparePairAgent()`/`resumePairAgent()` registers a provisional exact `{ pairId, role, sessionId }` Hub binding before calling DSH. Notifications for that ID may mark it dirty but cannot be derived until the returned live Session object identity is attached. Roll back provisional state and release any opened handle on failure.

Pair recovery uses this lifecycle and never holds the Pair mutation queue across DSH work:

```text
serialized: register Pair ownership as recovering
unlocked: resume Navigator and Pilot with provisional Hub bindings
unlocked: verify both live Session identities
unlocked: Bridge catch-up via runDerivedMutation groups
serialized: publish ready only if Bridge is healthy and both handles are owned
```

On catch-up failure, transition to failed, dispose opened handles while observation remains attached, drain resulting durable events if possible, then remove provisional/live bindings. No handle may leak and no path may recursively call `getReadyPair()`.

On resume:

```text
install hook
→ flush Navigator and Pilot
→ read both logs from seq 0
→ derive/sort missing groups
→ append idempotently
→ accept Pair input
```

Pair Registry must not publish `ready` until Bridge catch-up succeeds. A Bridge fault changes the Pair to a fail-closed unavailable state and exposes a diagnostic reason; no new message/Task/peer command is accepted while health is failed.

Use one shutdown owner. `PairCoordinator.close()` first stops Registry command admission, then invokes the Adapter's retry-safe `close()` exactly once. Adapter close owns Agent handle disposal and Bridge finalization; Registry cleanup no longer calls `adapter.close()`. Hosted `DshPairWebRuntime.close()` remains the sole Context-fiber owner and calls the idempotent Adapter close before disposing Context; a standalone Adapter with `ownsContext=true` disposes its own Context.

Adapter close performs:

```text
reject Pair followup and Peer tool admission
→ keep observation hook and Session bindings installed
→ await whenAgentIdle for both Agents
→ flush both Sessions and bridge.whenCaughtUp()
→ dispose both Agent handles without clearing observation bindings
→ flush retained Session objects and bridge.whenCaughtUp() again
→ detach Bridge hook and clear bindings
→ mark Adapter closed
→ hosted owner later disposes Context; standalone owner disposes it here
```

The second drain captures `aborted/disposed` or other close-time Session events. A native composer request racing shutdown is either owned by the still-live Agent and included before the second drain, or rejected by Agent disposal; the hook is never removed while an Agent handle can still append. Do not add a DSH patch solely for shutdown admission in P0.5.

Do not implement delivery append/wake exactly-once reconciliation; retain the documented P2 boundary.

If final drain or flush fails during close, retain hook, binding and retryable Bridge state and reject the close attempt. Do not delete Session-to-Pair ownership and then discover that a retry can no longer identify the Session. Only a successful final drain may unsubscribe and allow Agent/Context disposal.

After Adapter close succeeds, Coordinator tells Registry to clear closed handle references and subscribers without invoking Adapter again. Add retry-safe close state machines at Coordinator, Adapter and Hosted Runtime; do not memoize a rejected close Promise forever.
